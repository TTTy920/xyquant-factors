# RankIC 接入现有 XYQuant 插件方案

日期：2026-11-18  
状态：设计草案，供确认；未开始接入实现，未部署或启用服务器来源。

## 1. 结论与范围

沿用已选架构：**现有插件查找已授权因子 → 服务器按需导出 → 客户端安全下载与缓存 → 客户端计算 RankIC → 对话报告与附件**。

完成本方案后，客户可以只说因子名，Skill 查询真实目录、消歧，并只补问缺少的日期、日/周/月/季频率和全 A/静态自定义池。参数齐全、权限及数据契约通过时，后续取数、转换、运行和交付可以自动完成；首次 OAuth、名称歧义、缺参数、权限不足仍需要交互。

“自动寻找”限定为**当前账号可见且已登记的因子**，不扫描服务器任意文件、不绕过权限，也不自动把未登记文件加入目录。查目录不是发现因子后批量尝试导出，更不是遍历全库回测。

本轮仅只读核对插件与独立项目，并编写本文。不改插件、计算代码、连接配置或服务器，不创建真实导出，不上传本地数据，不初始化、提交或推送 Git。本文中的新增模块、契约字段与阶段交付均为拟议设计，不是现有可用接口。

### 部署位置

| 部分 | 放置位置与职责 |
|---|---|
| Skill、Python 计算与适配脚本 | 随 XYQuant 插件安装到客户执行环境；当前独立目录继续作为开发源 |
| 因子目录、授权、因子与基础数据导出 | XYQuant 服务器；复用已有能力，缺失的数据服务必须另行开发和批准部署 |
| 下载原件、规范缓存、任务配置、报告 | 客户项目目录；不写入插件安装目录、不随插件分发 |
| 七年本地参考包 | 保留在独立开发目录，只用于显式本地参考验证；不自动上传或改为正式来源 |

**无需把 RankIC 计算代码放到数据服务器，单纯上传 Skill 也不会接通调用链。** 这套方案不另建模型服务、不新增 Anthropic/OpenAI API 调用或隐藏模型 CLI，继续由现有客户端助手调用 MCP 和本地工具。

### 架构取舍

- **采用：服务器按需导出、客户端计算。** 复用现有插件模式与本地引擎，改动集中在数据接入；客户环境需 Python 和安全下载能力。
- 不采用“把全部数据随插件发给客户”：分发体积、授权隔离和更新不可控；本地参考包不等于客户的授权数据。
- 不采用“新增服务器 RankIC 任务”：可减少客户端下载，但要新增计算 API、任务资源治理与部署运维，超出当前目标。

## 3. 目标调用链与停止位置

```text
客户因子名 / 已提供参数
  → 原生 MCP 连接、账号授权
  → 查目录、准确标识、歧义确认
  → 只补问缺失参数
  → 已验收适配版本 + 当前账号权限 + 基础数据能力预检
       不满足：保存非敏感参数，明确缺项，停止；不创建因子任务
  → 查合格缓存；必要时先取正式日历
  → 按真实日历计算观察 T 与下一周期卖出日，确定价格需求
  → 缓存未命中的基础数据与准确因子导出
  → 宿主安全交接、校验下载、受限解压
  → 按已审文件结构转换，生成正式规范快照
  → 助手生成无凭据配置，调用本地 RankIC
  → 读取真实状态、诊断和报告，在对话交付三类结果
```

“预检先于导出”指先核实服务存在、契约经审、权限及可提供范围；不要求尚未下载的数据先完成逐值验证。预检通过后可获取必要日历以规划边界，但**不为已知无法运行的正式任务创建因子导出**。实际文件不符合预检声明时仍须失败，不能以预检成功替代内容校验。

### 期间规划

复用现有引擎的周期规则，不另写一套以自然工作日估算的算法：

- 起止日期含首尾，只限制因子观察 T；日频卖出为下一真实交易日。
- 周/月/季均为已关闭自然周期末最后交易日，到下一同频自然周期末最后交易日；不能把查询截止日当周期末，也不能跳过空周期。
- 先请求日历完整性所需自然边界；日频查找下一交易日若尚不明确，按服务可用范围有界扩展，达到范围/次数上限即停止或标记未完成，不无限查询。
- 因子覆盖只需满足所选观察日；价格与日历需要延伸到收益终点。例如 2025 年第四季度的观察可能需要 2026 年一季度末价格。
- 服务缺失、权限不足、历史必要数据不覆盖：预检阻塞，不偷偷缩短区间。已知日历下尚未产生的未来卖出价：按原引擎保留 incomplete，不填零或伪造价格。

## 4. 服务器需要提供什么

### 已有能力的使用原则

优先沿用 `query_factor_catalog`、`create_export`、`get_export`，但实现前必须读取当前原生工具 schema，并取得维护者允许的真实小样本。本文不猜 create_export 的完整参数，不把示意字段当可调用参数，不假设基础数据已有某个 dataset 名称。

不能把“服务器磁盘上有文件”视为“客户通过 MCP 能取得文件”。若基础数据没有正式出口，这是服务侧缺口：先交付接口设计，再单独批准实现和部署；本轮及后续纯客户端阶段不通过 SSH/SCP、容器或代理绕过。

### 待验收的最小能力契约（语义要求，不是现有工具 schema）

| 能力/数据 | 必须有的语义与证据 |
|---|---|
| 因子目录 | 稳定唯一 ID、名称/定义、授权可见范围、覆盖、版本/更新语义；别名歧义可识别 |
| 因子导出 | 准确 ID、请求条件、数据版本/快照、实际覆盖、字段与类型、原件大小/SHA、完整任务状态；不能只靠文件名绑定因子 |
| 复权收盘 | T 与卖出日同口径 adj_close；复权定义、分红/拆并股处理、adjustment_id 与版本说明及可复核样本；不能由收益率拼猜 |
| 完整日历 | date 以及自然日期 complete_from/complete_through；说明交易所/市场口径，区分未来交易安排和已产生价格 |
| 历史在市 | 全 A 必需：历史 T 的 1/0/未知及原键存在性，包含退市历史、代码变更和覆盖限制；不能以 eligible 或当前存活名单代替。静态自定义池不强求历史成员全集，不能因此改变其既有计算规则 |
| 授权与股票范围 | 当前账号的非敏感授权分区标识、允许的因子/代码/日期范围、权限版本或指纹、缓存使用规则；来自可信授权服务，不由模型自填 |
| 跨数据一致性 | 因子、日历、价格、在市各自版本与兼容关系；同一次运行不得任意混用不同复权快照、权限或不兼容修订 |
| 任务与下载 | 幂等请求、状态/失败/到期含义、原生授权下的下载描述、受限文件凭据；确认安全下载器支持真实来源与路径 |

全 A 的统计范围需明确：按账号获准的历史 A 股范围计算；若账号并非全市场权限，必须标为“授权范围内 A 股”，不能冒称完整全 A。自定义池范围外的代码不能为凑样本而替换；按既有规则记录范围外排除，授权交集不足则 no_result。

因子通常与价格有不同数据版本；不强求所有服务返回相同字符串 snapshot_id。必须由提供方声明兼容性，规范包记录各角色原版本和一次组装快照，不能仅因日期重叠就混拼。

### 首次需要的验收材料

提供方数据定义与字段文档、当前工具 schema、去凭据的任务元数据、允许保留的真实导出原件、文件 SHA/大小、复权及上市/退市/缺失样本、权限/版本与日历完整性声明。验收材料存放范围遵守授权，不把原面板提交到公共仓库；测试夹具以合成数据为主。

## 5. 安全自动下载：独立的发布前阻塞项

现有下载器只是消费 ready 任务 JSON。终端 getpass 可避免交互回显，但**不能证明助手能自动把 MCP 返回值安全交给本地进程**。把 JSON 写进 shell 命令、Here-String、聊天或临时文件均不满足约束。

目标接入边界：宿主的可信执行层在内存中接收原生授权返回的下载对象，序列化写入下载子进程 stdin；模型可见调用只带非敏感 job_id、项目位置等，执行结果只回传本地路径、校验值与安全状态。若原生 MCP 工具会把凭据直接记录到模型对话或宿主工具日志，单纯在后面加 stdin 仍不够，必须由宿主提供凭据截获/遮蔽的可信交接能力。

这一能力**本轮未发现可证明已存在的宿主实现**。实施时先验证目标客户端能否提供；不能提供则停止“全自动下载”承诺。不得通过读取 OAuth 缓存、自建未获准登录流或复制私钥补洞。需要宿主或服务侧新增能力时，另行设计、授权和验收；不把某个拟议本地工具名称写进 Skill 当成已存在功能。

必须保留的下载约束：

- 原生 OAuth、既有 TLS 校验、固定 HTTPS 来源/任务路径、拒绝重定向、凭据到期、空间/大小限制、锁和有限重试；不为了接通而放宽白名单。
- 创建失败/响应丢失时先用原 request_id 查找，重试同一条件复用编号；不重复收费式地批量创建。已终止或过期任务按真实服务约定处理，不能把旧编号绑定到新条件。
- 原件大小和 SHA 完整校验后才转换；下载到期时重新取得同一任务的凭据，不把新 ticket 写进状态文件。
- ZIP 继续使用 rankic_archive 的路径、链接、成员、压缩比与总量检查；单文件也只读取已验收数据格式，拒绝执行/反序列化下载内容。
- 读取下载数据使用 Python -I；脚本与下载目录隔离，不从下载/解压目录启动解释器。
- 当前 rankic.py 使用同目录 imports，不能简单加 -I 就假定可运行。正式接入需提供可信启动器/包入口并测试：仅加入受信任代码目录，不把项目或下载目录加入导入路径。

## 6. 客户端模块与数据结构

保持单一计算引擎，新增能力在输入层与调度层，避免改动 RankIC 数学口径。

| 模块 | 责任、输入和输出 | 实施性质 |
|---|---|---|
| SKILL.md | 因子发现、消歧、缺参数补问、调用宿主 MCP 与本地入口、读取报告 | 更新现有指引 |
| rankic_workflow.py | 非敏感任务状态、参数、预检与期间计划、缓存查询、组装、调用现有 CLI；不读取 OAuth，不假装普通 Python 能直接调用宿主 MCP | 拟新增本地编排模块，命令需实现后确定 |
| rankic_server_adapter.py | 输入已验收原件及可信非敏感清单；按契约版本显式映射字段、长宽转换、生成规范包和来源证据 | 拟新增；不猜列名、ZIP角色或格式 |
| rankic_cache.py | 当前授权/版本校验后匹配缓存；完整性检查、staging 和原子发布；无下载权限不因本地有文件而放行 | 拟新增 |
| rankic_download.py / rankic_archive.py | 保留原件下载及安全解压，不计算、不创建任务、不推断因子 | 复用并补真实联调测试 |
| rankic_store.py / rankic_inputs.py | 正式 schema/scope 准入、数据验证、按需读取和输入元数据 | 经审扩展，不仅删除 origin 拒绝 |
| rankic_engine.py | 原有四频收益与 Spearman | 原则上不改；若输入边界需调整必须单独回归证明 |
| rankic_report.py | 加入非敏感正式来源/覆盖/授权范围说明 | 定向扩展，不写凭据或原面板 |

### 数据包演进

- 保留 schema_version=1 的 local_reference 行为和原基线。正式服务器采用拟议 schema_version=2，显式携带授权范围、契约/适配版本与各角色来源绑定；具体字段需在服务能力验收后冻结，不由聊天生成即视为有效。
- 维护者发布的适配版本只接受经审的契约版本及可信来源链；本地自填 verified、文件 SHA 或 origin 不构成授权证明。权限绑定需由可信执行层与授权服务核对，并绑定清单摘要；签名若被选用，也必须有完整签发/验签/撤销设计，不能只留一个布尔字段。
- validate_origin、Store、DataBundle 的所有准入点一并设计；本地参考仍显式隔离，不把服务器数据改标 local_reference。旧版固定拒绝一直保留到对应正式版本通过发布闸门。
- 规范表继续沿用现有 date/stock_code/value、adj_close、listed 和两个 presence 字段。转换前先检查原键唯一性；不能用去重、填零、前填、内连接缩池来“修好”输入。
- 原件转换要核对全部参与转换的键、值及空值/presence；SHA 证明字节一致，不证明复权含义或历史成员完整。
- 不能调用只允许本地参考的 prepare_sample 或 HDF 扩充工具来伪装正式适配器。

### 客户项目布局（目标）

```text
<project>/
  downloads/factors/<job>/              已有因子下载原件与无凭据状态
  downloads/rankic-base/<job>/           拟议基础数据原件目录；需正式下载契约支持
  downloads/rankic/<snapshot>/
    catalog.json
    provenance.json
    calendar.pqt
    market/YYYY.pqt
    factors/<id>/YYYY.pqt
  downloads/rankic-tasks/<request>/      无凭据任务参数与状态
  results/rankic/<UUID>/                report.md / rankic.xlsx / metadata.json
```

基础数据下载不能强行塞进仅认因子任务路径的下载器。实际基础数据任务采用什么 URL/目录，由正式契约确定后实现受限适配；上面的目录是本地规划，不是新服务器端点。

缓存键至少绑定来源、当前账号授权分区及权限指纹、准确因子 ID、各角色版本、复权标识、规范化/契约版本、覆盖与文件摘要。按年存储不等于必须全量下载七年；先复用合格已需分片，再取缺失范围，禁止按文件名或年份盲目命中。

账号切换、权限收回、版本或复权修订后，不复用旧权限数据继续正式执行；按服务规则重新验证。正式请求不能仅因离线就跳过当前授权核对。不同版本缓存不可原地覆盖；任务和临时 SQLite 隔离。已坏缓存不当成功、不自动删历史数据；重取写新 staging，成功后发布新快照，清理仍需遵守用户授权。

## 7. 同步回现有插件的方法

独立目录继续是 RankIC 开发源；通过受控、可复核的文件清单同步到 `plugins/xyquant/skills/factor-rankic/`，不维护两套不断分叉的计算实现。第一版使用显式同步清单和差异检查，不引入新的通用发布平台。

### 拟同步与修改范围

- 同步运行必需的 rankic CLI、engine、inputs、store、report、download、archive、requirements；新 workflow/adapter/cache 通过验收后一并同步。

## 8. 分阶段实施与退出条件

各阶段依赖前一阶段结果，不并行猜测接口；本轮只交付设计，以下不是实施授权。

| 阶段 | 要做的工作 | 交付与通过条件 |
|---|---|---|
| A. 冻结接入契约 | 确认当前工具 schema、基础数据出口、权限/版本关系、真实文件格式、目标客户端安全交接能力 | 可核查的契约与差距清单；基础服务或安全交接缺失时明确阻塞，不先删闸门 |
| B. 准备服务能力（仅确有缺口） | 单独设计和批准所缺数据出口/宿主交接能力；不新增 RankIC 计算 API | 在获批测试环境提供可验收能力；生产修改与部署另行明确授权。已有能力满足则跳过新增服务开发 |
| C. 独立客户端实现 | 先合成测试后实现适配、正式准入、缓存、编排与可信启动器；现有离线模式不变 | 模拟正反路径通过；服务器固定拒绝不被普通配置绕开；不把合成通过当真实联调 |
| D. 受控真实联调 | 在已获准测试账号/环境取真实小范围原件，逐角色对照和四频运行，再测全 A 覆盖 | 真实来源链、转换证据、期间/IC/报告对照及授权隔离通过；不能仅试一次下载 |
| E. 插件预发布与启用 | 按清单同步、更新版本/说明、完整回归、实际 ZIP 安装/解压验证 | 客户端能从提问到真实报告；只有通过的客户端列为支持；维护者确认对应正式适配版本后启用 |

契约、权限、安全输入通道都未确认前，可做非敏感目录与参数准备，但不能声称正式自动回测已可用。D 阶段使用 C 阶段产出的、完成契约审查的未发布候选版，在明确获准的测试环境验证正式输入策略；旧分发版保持固定拒绝，不用用户可填开关或改来源标签绕过。E 阶段通过前不向正式客户开放该候选能力。

若要先发布离线升级版，应继续明确标注只支持本地参考，不能把它当 E 阶段完成。

## 9. 验收标准

### 功能与口径

- 仅给因子名：查真实目录，只问缺少的日期、频率、股票池；已给参数不重复问。歧义必须选择，找不到/无权限不猜 ID。
- 一个在正式目录和基础数据内均有授权的准确因子，在同一观察区间完成日/周/月/季四频；固定已实现收益区间，与独立参考计算逐期核对 T、exit、样本数、IC 和汇总。
- 专门验证日历节假日、跨年季度、查询截止不在周期末、缺/空周期、未形成卖出价格；不得用观察截止日截断收益。
- 含上市/退市、不同股票轴、present-null/缺键、并列秩、常量、小样本、非有限值/非正价格、重复键的用例维持既有口径；默认 min_stocks=20，不为通过而自动降为3。
- 全 A 披露当前授权范围、历史成员 unknown_universe 及 partial_success；自定义池至少测一个小池、范围外与不足阈值场景。
- 本地 2025 年3月参考四频基线与既有迁移重放仍一致；145通过/2跳过是此前147项测试的历史结果，正式实现后必须重跑当时的完整测试，逐项报告新增、失败和跳过，不能借用旧数字。

### 端到端、缓存与失败

- 首次真实执行下载并生成三份报告；第二次同授权/版本/覆盖命中缓存，不再创建不必要导出，但仍遵守当前授权检查规则。
- 更换账号、撤权、同名不同 ID、因子修订、复权修订、清单/文件损坏、覆盖不足均不错误命中旧缓存。
- 导出响应丢失、网络重试、凭据到期、失败/取消/任务到期按真实服务契约终止或恢复，不重复创建、不留“成功”的半成品。
- SHA/大小不符、转换角色不符、ZIP越界/链接/压缩炸弹、目录污染、磁盘空间不足和并发任务有明确失败状态；不写出可被当成完整数据的快照。
- 基础服务缺失、未验收契约、无安全凭据通道时，在因子导出前停止；不 SSH、不 fallback 到本地参考、不伪造 verified。
- 宿主日志、命令历史、聊天、状态文件、异常和报告均无 ticket/token/下载 URL；安全输入通道有真实执行证据，不只看文档描述。

### 分发与交付

- 用实际发布 ZIP 在新目录、新建环境运行，不依赖 D:/XYQuantPlugin、原 HDF、独立开发目录或开发者 venv；普通计算无 h5py 导入、无 HDF访问、无计算阶段网络访问。
- Windows 作为首个实际支持环境；原插件宣称的 macOS/Linux 及不同宿主分别验证安装、Python启动、安全交接、路径和MCP能力后再承诺支持，不因同一ZIP就声称跨平台自动通过。
- 对话直接呈现参数、观察/实际收益区间、状态、有效/无效/未完成期、均值、ddof=1标准差、未年化ICIR、正值比例、股票数和覆盖限制；同时链接本次 Markdown/Excel/JSON。
- 不足两期或零标准差的未定义指标保持 null；短样本不外推显著性或可获利。Excel 暂仍为公式加 Python 缓存；独立表格引擎重算未验证时继续披露，不让该限制变成虚假的已验收项。

## 10. 发布与回退边界

正式支持不是一个客户可填的开关，而是：**服务契约与权限链可核查 + 安全下载通道可执行 + 转换和四频真实对照通过 + 插件安装包通过 + 维护者确认发布**。

回退保留上一插件包和数据快照；发现契约或权限问题时停止对应正式适配版本、回到明确的“服务器回测不可用”状态，不把正式请求重定向到本地样例。不覆盖旧缓存，不删除客户报告；如需任何服务器回退，单独按获批部署流程执行。

当前最先需要完成的是阶段 A：核实正式基础数据与安全交接契约。它决定能否直接做客户端适配，还是先补服务/宿主能力。本文未执行任何阶段，未改动现有服务器闸门，也未取得生产部署、Git提交或推送授权。
