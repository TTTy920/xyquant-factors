# 个股排名与持有诊断

客户只需提供一只股票代码，例如 `600519.SH`。默认截至上海时间今天并查全部四个策略；可指定历史截止日或一个策略（接收目录给出的明确别名，执行时用规范名）。只有代码、日期或名称有歧义时补问。不需要客户提供服务器密钥、账户密码或持仓文件。

## 授权取数

使用当前宿主授权的 **XYQuant MCP**；没有连接时按 [xyquant-login](../xyquant-login/SKILL.md) 使用宿主自己的授权流程。OpenCode 用 `/mcps`。不能用 SSH、网页会话、其他账号或离线样例代替授权。切换账号或失去权限后，不拿上一个账号的本地缓存当当前数据。

### 四因子同日截面

1. 用 `query_factor_catalog(factor=...)` 读取四个确定的 ID、目录排序方向、有效授权及数据覆盖。规则版本 v1 固定为 `ROE_TTM`、`EP_TTM` 降序（大值排名优先）；`CloseTrend_240D_Reg`、`Amount_20D_Avg` 升序（小值排名优先）。目录与此不一致时报告冲突，不把值反号或用其他因子顶替。
2. 以四个因子实际覆盖上限、授权上限和查询截止日的最早值为候选。若候选无同日数据，可用无股票筛选的预览**只验证日期是否存在**，在候选日前至多回查 7 个自然日（不越过共同授权或覆盖起点），只接受全部四因子确有数据的同一日。不把预览行用来排名，也不因目标股票缺值而改日期。更早或不完整的覆盖须明确，不编造日期。
3. 生成 UUID 作为 `request_id`，调用 `create_export(factors=[四个ID], start=T, end=T, request_id=...)`。**不传 `codes`**；只导出目标股票就不能计算截面排名。按服务建议查询 `get_export` 至 `ready` 或明确失败；重试复用原编号。用 `get_export(job_id=..., include_download=true)` 获得短期下载凭据。按下文把任务交给下载器；使用当前任务的 ID、日期和 SHA-256，不从文件名猜。

### 两期持仓快照

1. 用 `query_stock_data(dataset="catalog")` 读取 `original_attribution`。默认策略为 `300增强`、`xgb500增强`、`xgb1000增强`、`xgb2000增强`。`query_strategy_research` 的净值和介绍不是持仓。以持仓文件和快照清单为准，不以压缩包生成日期代替持仓日期。
2. 优先读取当前授权版本下**已有、未过期且能单独通过清单校验**的策略权重和快照。数据包沿用服务器固定 1 小时有效期；到期重新查询目录并下载当前版本。不必因同归因包缺少无关的 Barra 或行业文件而丢弃可用持仓。可用 [归因下载器](../portfolio-attribution/scripts/download_original.py) 检查完整项目缓存：

   ```text
   python <归因Skill>/scripts/download_original.py status --project <项目绝对路径> --data-version <目录版本> --manifest-sha256 <目录清单SHA-256>
   ```

   已有可用数据先分析，不重复下载。完全没有可核对的权重时，用 UUID 调用 `query_stock_data(dataset="attribution_bundle", data_version=..., request_id=...)`，不传日期或股票筛选。只传 `job_id` 查询就绪任务；使用返回的版本及清单 SHA-256，必须与发起任务时的授权目录相符。版本过期则重查目录，不猜缓存路径或版本。大包在工具时限内未完成时，可先交付其余结果与可核对的持仓目录，不把下载中或目录信息当实际权重。避免重复发起同版本下载。
3. **按可得数据分别给出结果**：两期完整快照计算股票仓位内占比变化；只有一期完整快照报该期；仅权重文件中单条正数记录可校验、但快照不完整时，单列「未确认完整的原始记录」，不把原始值转成百分比，不算变化或断言未持有。只有目录时显示其历史覆盖，权重及增减均标未知。详见[持仓可用性规则](references/holdings.md)。

### 安全交接

安装 [requirements.txt](requirements.txt)，使用 Python 3.10+。在支持可信非回显 stdin 的宿主，把原始任务 JSON 作为数据送入下方 `save`，不要让凭据进入聊天、日志、文件、命令行参数或代码文本：

```text
python <本Skill>/scripts/mcp_transfer.py save --kind <factors或holdings> --job <任务ID> --project <项目绝对路径>
```

OpenCode 可使用[单次回环交接](references/host-transfer.md)；不将 MCP 的带票据结果作为 Code Mode 输出。若没有可用的安全交接，报告阻塞，不回显任务对象或改用 SSH。归因包约百余 MB，由本地下载器流式下载；它不是 MCP 工具响应的一部分。

## 公开新闻取数

每次诊断默认用宿主的网页搜索查目标股票，可和 MCP 取数同时进行。用股票代码和核实后的公司简称检索，**只传公开标识，不把客户持仓、账户信息或因子数据发送给搜索工具**。查截至查询日（含）最近 7 个自然日，打开原文核对主体、发布日期和事实，优先交易所公告、公司披露和可靠财经媒体。相同事件只保留一条，最多展示两条，不足不凑数。

按 [新闻证据与分析规则](references/news.md) 整理公开条目；在命令上加 `--news-stdin`，把 JSON 作为数据传入标准输入。没有搜索工具或打不开可核对的来源时说明限制，不猜新闻，也不把公开网页当成 XYQuant 授权数据。

## 计算与交付

```text
python <本Skill>/scripts/diagnosis.py --stock 600519.SH --project <项目绝对路径> --factor-job <因子任务ID> --factor-date YYYY-MM-DD --factor-sha256 <因子包SHA-256> --attribution-version <归因数据版本> --manifest-sha256 <归因清单SHA-256>
```

可加 `--as-of YYYY-MM-DD`（不指定则用上海日期）和 `--strategy <规范名>`（可重复）。下载未完成时仍可将实际 MCP 归因目录和新闻一起走 `--context-stdin`，格式见[持仓规则](references/holdings.md)，与单独 `--news-stdin` 二选一。无法取因子时省略其全部参数；归因只在得到有效版本和清单时传两项版本参数。读取实际 stdout JSON 和退出码，不凭运行命令就宣称成功。`success` / `partial_success` 返回 0，`no_result` / `error` 返回 2。取数失败不能说成零持仓或股票零分。

按以下顺序直接在对话中呈现，不要求用户打开附件：

1. **持有判断与依据**：`supports_holding` 支持继续持有，`does_not_support_holding` 不支持继续持有，`review` 观望复核，`insufficient_data` 数据不足。只按本程序的等权 v1 规则：至少 3 项进入各自最佳 30%，且无一进入最差 30%，才支持继续持有；反向同理。采用并列组中点分位，前后边界含 30%/70%；有效排序少于 3 项或因子距截止日超过 7 个自然日时不下方向性结论。列明缺因子、无回测验证、未全面核验风险状态等限制。新闻和历史持仓不参与 v1 打分。若 `news.requires_risk_review=true`，在判断旁单列「事件风险：先复核」，不要把因子结论当成对该事件的覆盖。
2. **因子排名表**：截面日期、原值、名次 / 有效样本数、并列情况、排序方向、相对位置。使用账户授权导出中的 A 股代码范围，尚未独立核对该日在市全集，不称全 A。分母按各因子独立计算，缺值不填零。相对位置越靠近 0% 名次越靠前。成交额按模型偏好低值排序，不解释成流动性更好，也不称综合排名。
3. **策略持仓表**：每个所选策略都列一行，展示可得的快照、股票仓位内占比、变化百分点和状态。与归因引擎口径一致，占比为原始记录值除以该期已核对的股票持仓合计，不含现金，不是账户总资产占比；不要把原表 `weight` 直接当小数权重。有两期用两期，只有一期只报当期；缺权重时展示目录覆盖日期或明确没有可用资料。只有完整快照中该股票无行才能报未持有。未确认完整的正值记录单列说明，不进入策略增减和已持有统计。用 `holdings_summary` 说明多少策略能对比、多少持仓状态未知；不同策略日期可能不同，不合计权重，不把未知当零。标为「历史参考」，不是当前持仓或交易流水。
4. **最新新闻与影响**：根据 `news.items` 列 1–2 条已核对的独立事件，逐条写明日期、来源、原文链接和一句话摘要；最后用一句话说明对持有分析有什么补充或仍需验证什么。新闻晚于因子截面时明确属于截面之后的新信息，不据此解释已经发生的排名变化。不把机构观点当成公司披露，不把找不到新闻当作没有风险。数值结果为 `no_result` 时，仍可展示已核对的新闻，但不能用新闻补出缺失的四因子持有结论。

报告只展示客户股票和必要的聚合统计，不转述全量数据、内部任务号、凭据或本地缓存路径。除非出现明确边界错误，不擅自改动阈值、日期、股票池、策略及排序口径。
