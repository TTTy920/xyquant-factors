# 策略选股归因

使用 `explain_strategy_selection(strategy, month, symbol)` 读取服务端已接入策略的月度选股解释。服务端根据已有策略评分表和发布规则计算，Skill 负责确定查询条件并解读结果。

## 确定查询条件

- `strategy`：用户指定的策略名称、明确简称或已经查询到的目录标识。缺少策略或存在歧义时询问，不猜测标识，也不将同名策略拼成一个结果。
- `month`：选股明细所属月份，格式 `YYYY-MM`。从用户提供的明确日期提取月份；未给月份时询问。用户要求最新一期时，以可查询到的实际数据覆盖为准，不直接采用当前自然月。
- `symbol`：查询单只股票时传入六位代码和交易所后缀，例如 `600519.SH`。无法确定交易所时询问。用户要看当月分组名单时省略此项；不把单只股票查询扩大为全名单。

先确认当前宿主提供该工具。已安装版本尚未暴露工具时，说明需更新插件；不要把不存在的工具调用写成成功。已有有效连接直接查询；只有返回需要登录或授权失效时，才按同包 [因子查询与下载的登录流程](../factor-download/SKILL.md#连接账号) 连接账号。权限不足、入口关闭、策略未接入与当月无数据分别说明，不通过重新登录或其他接口绕过限制。

## 解读结果

先给出策略、月份和实际明细日期。根据查询范围，展示个股结果或服务端返回的分组名单，保留组内排名、综合分、组内名额与名额线综合分。

- `按规则入选` 或 `按规则未入选`：说明排名与组内名额的关系；有边界参照时，结合参照股、综合分差和主要驱动解释优势或不足。
- `名额线并列待定`：保留待定结论、同分股票数和待定名额，不按股票代码或自己的判断替策略决定入选名单。
- `当期已有明细中无记录`：只说明该股票未出现在当期已接入明细中，不据此断言其触发了某条过滤规则。
- 部分分组缺失或当月无数据：明确实际覆盖与缺失分组，不填零、不推算缺失名单。

对主要驱动沿用返回的因素名称、分数及“排名影响”。`综合分差贡献` 是相对边界参照股的评分差异，保留正负号，不能改写为收益贡献、涨跌幅或百分比。服务端只展示主要驱动，未返回的评分项不补造；也不把这些主要项加总后称为完整分解。

两股有效评分项不同或仅提供本股依据时，遵循返回的解释口径，不强行做逐项贡献比较。解释评分对名额线的影响，不声称已经证明真实交易原因或重新运行了回测。

## 回答范围

将结论表述为“按当期评分和组内名额推算的选股结果”。回答用户关心的入选、落选或评分驱动，按需使用紧凑表格。查询多个月时分别保留每月的分组与名额线，不混用不同月份的参照股。

该流程解释选股决策；用户询问组合风格暴露或风格收益贡献时，转到同包的 Barra 归因工作流。原始评分明细、内部路径、凭据及接口版本不加入用户报告，不另行下载未开放的原始评分表。
