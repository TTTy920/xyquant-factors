# 本地输入

输入是 UTF-8 JSON，包含查询条件、列名映射、分组规则和原始记录。此例为合成数据：

```json
{
  "strategy": "合成策略",
  "month": "2026-10",
  "symbol": "000002.SZ",
  "columns": {"date": "日期", "symbol": "股票代码", "score": "综合分"},
  "groups": [
    {
      "label": "全市场", "sheet": "评分表", "quota": 1, "order": "descending",
      "dimensions": [
        {"column": "盈利分", "label": "盈利", "weight": 1},
        {"column": "质量分", "label": "质量", "weight": 1}
      ]
    }
  ],
  "tables": {
    "评分表": [
      {"日期": "2026-10-30", "股票代码": "000001.SZ", "综合分": 0.8, "盈利分": 0.9, "质量分": 0.7},
      {"日期": "2026-10-30", "股票代码": "000002.SZ", "综合分": 0.6, "盈利分": 0.5, "质量分": 0.7}
    ]
  }
}
```

- `symbol` 可省略，返回各组按规则入选和名额线并列待定的名单。
- 每个 `sheet` 对应 `tables` 的一个记录数组。全部已配置分组都要有表；空表使用 `[]`。月份缺失会保留为覆盖缺失。
- `quota` 为正整数；`descending` 为高分优先，`ascending` 为低分优先。名次采用竞争排名，同分不以代码破除名额线并列。
- `dimensions` 可省略或为 `[]`，此时只解释排名。配置维度后，每行须包含对应列，缺失值显式使用 `null`。综合分应等于有效评分项按正权重重新归一后的加权平均，误差容限为 `1e-8`。
- 评分维度可增加 `components`，格式为 `{"子项列名": "显示名称"}`。每行提供这些子项列，缺失用 `null`；维度得分必须等于其非空子项均值。两股有效子项不同，不做逐项分差贡献比较。
- 日期为 `YYYY-MM-DD`，同一月份只能有一个明细日期；同月同股在所有分组中只能出现一次。数值不得为布尔值、NaN 或无穷大。
- 不要先删掉落选股票：完整组内排名及边界参照需要当月整个候选组。输入只有持仓名单时，不能据此解释其他股票为何落选。

脚本保留原综合分及维度值，不计算原始财务或价量因子，也不执行股票池筛选。输入映射与原策略评分不相符时会报错，不自动调整权重。
